# Планировка → 3D: прототип генератора

Мини-прототип под задачу «превратить исходные данные и правила дизайна в 3D-модель и проверяемый результат».
Демонстрирует то, что заявлено в вакансии: работа с геометрией, генерация объектов по правилам,
интерактивная 3D-сцена и вычислительная логика, связанная с данными.

## Что делает

1. Читает описание помещения в JSON (миллиметры): контур стен, толщины, высоты, проёмы (двери/окна), перегородки, мебель.
2. Строит 3D-сцену: стены собираются панелями с вырезами под проёмы, окна — стекло, пол/потолок — по внутреннему контуру,
   мебель — параметрические блоки по типу объекта.
3. Считает метрики «как для сметы»: площадь пола, периметр, объём, площадь стен нетто (за вычетом проёмов), занятость пола.
4. Проверяет правила дизайна и подсвечивает нарушителей в 3D:
   выход мебели за контур, пересечения мебели, врезка в перегородку, перекрытый проём, зазор до стены, занятая зона перед дверью.
5. Экспортирует сцену в `.glb` (дальше открывается в Blender/Unity/Unreal).

## Запуск

```bash
npm start                  # python -m http.server 8000
# открыть http://localhost:8000/
```

Страница без сборки и без зависимостей в репозитории: three.js подключается по importmap с CDN.

Полезные ссылки:

- `http://localhost:8000/?plan=plans/demo_2rooms.json` — сразу план с нарушениями
- `http://localhost:8000/?view=top` — вид сверху

## Тесты логики

```bash
npm test                   # node tests/run.mjs
```

Покрыто тестами (19 проверок): площадь и знак обхода полигона, смещение контура внутрь (в т.ч. с разной толщиной стен),
SAT-пересечение ориентированных прямоугольников, расстояния до отрезков, разбор плана, метрики, отказ на некорректных данных
(незамкнутый контур, проём за стеной, проём выше стены, неизвестные единицы измерения), срабатывание каждого правила.

## Структура

```
index.html            интерфейс: выбор плана, JSON, метрики, список нарушений, экспорт .glb
css/style.css         оформление панели и вьюпорта
js/geometry.js        чистая 2D-геометрия: векторы, полигоны, inset, SAT, расстояния
js/plan.js            разбор и нормализация плана + метрики (единицы, проверки входных данных)
js/rules.js           валидатор правил дизайна, список нарушений с кодами
js/build.js           построение three.js-сцены из плана
js/main.js            связка интерфейса, логики и сцены
plans/*.json          примеры исходных данных
tests/run.mjs         тесты чистой логики (Node, без браузера)
tools/screenshot.py   headless-скриншоты
```

## Формат входных данных

```json
{
  "units": "mm",
  "rules": { "minWallClearance": 50, "doorClearance": 900 },
  "walls": [
    { "id": "w-south", "start": [0, 0], "end": [4200, 0], "thickness": 150, "height": 2700,
      "openings": [{ "kind": "door", "offset": 2600, "width": 900, "height": 2100, "sill": 0 }] }
  ],
  "partitions": [],
  "furniture": [
    { "id": "sofa", "type": "sofa", "pos": [1300, 526], "w": 2000, "d": 900, "h": 800,
      "rotation": 0, "againstWall": true }
  ]
}
```

- `walls` — замкнутый контур по часовой или против часовой стрелки; осевые линии стен, толщина уходит наружу/внутрь поровну.
- `openings` — проём задаётся смещением от начала стены (`offset`), шириной, высотой и подоконником (`sill`);
  `kind`: `door`, `window`, `passage`; `checkClearance: false` отключает проверку свободной зоны перед проёмом.
- `furniture` — центр проекции (`pos`), габариты (`w`, `d`, `h`), поворот в градусах; `againstWall: true` — встроенный объект,
  ему разрешено примыкать к стене (для остальных требуется зазор `minWallClearance`).

## Коды нарушений

| Код | Что означает |
| --- | --- |
| `FURNITURE_OUT_OF_ROOM` | объект выходит за контур помещения |
| `FURNITURE_OVERLAP` | два объекта мебели пересекаются (SAT, с глубиной проникновения) |
| `FURNITURE_OVERLAP_WALL` | объект врезается в перегородку |
| `OPENING_BLOCKED` | объект перекрывает проём |
| `WALL_CLEARANCE` | зазор до стены меньше нормы и объект не помечен как встроенный |
| `BUILTIN_GAP` | объект помечен встроенным, но отходит от стены |
| `DOOR_CLEARANCE` | занята свободная зона перед дверью |

## Осознанные ограничения (что дальше)

- Внутренний контур считается смещением осевых линий внутрь — корректно для выпуклых и ортогональных контуров
  (все примеры такие); для сложных Г-образных помещений нужен алгоритм offset с самопересечениями.
- Стены собираются разбиением на панели, а не булевыми операциями CSG: быстрее и предсказуемее, но не поддерживает
  произвольные арочные проёмы и ниши.
- Правило «зона перед дверью» проверяется с обеих сторон проёма, поэтому для межкомнатных дверей возможны ложные
  срабатывания — отключается флагом `checkClearance: false` (так сделано в `demo_2rooms`).
- Проверка проходов между объектами (нормативные коридоры) пока не реализована — следующий шаг вместе с привязкой
  норм (СП/ГОСТ) и автоматическим подбором расстановки (оптимизация/эвристики).
- Единицы измерения — метры/миллиметры; импорт DWG/IFC/PDF-планировок не реализован (это отдельный слой парсинга).
